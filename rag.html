RAG: Making AI Answer From Your Own Data

Models don't know your company docs, your notes or yesterday's news. Retrieval-augmented generation (RAG) fixes that by finding the right information first and handing it to the model.

What RAG is

RAG is an open-book exam for the model. Instead of hoping the model memorised the answer, your code retrieves relevant passages from your documents and puts them in the prompt, then the model generates an answer grounded in them, ideally with citations.

It reduces hallucinations, keeps answers up to date (just update the documents) and lets you use private data without training a model.

The RAG pipeline

1. Ingestload PDFs, web pages, docs; clean the text
2. Chunksplit into passages of a few hundred words
3. Embed + indexturn each chunk into a vector and store it
4. Retrievefind the chunks most similar to the user's question
5. Generateprompt = instructions + retrieved chunks + question

Chunking documents

Chunks that are too big waste context and dilute relevance; too small and they lose meaning. A common start is 200–500 words with a little overlap, split on natural boundaries like headings and paragraphs. Keep metadata (title, URL, date) with each chunk so you can cite sources.

Embeddings and vector search

An embedding is a list of numbers that captures a text's meaning. Texts about similar things have vectors that point in similar directions. A vector database (or a simple library) finds the chunks closest to the question's embedding. That's semantic search: "refund" can match "money back".

Many production systems combine this with keyword search (hybrid search) and then re-rank the top results for better precision.

Making RAG good

  • Evaluate retrieval separately: did the right chunk appear in the top 5?
  • Tell the model to answer only from the provided context and say when it isn't there.
  • Show sources so users can check.
  • Watch for stale or duplicate documents; garbage in, garbage out.

RAG on this website

The agent's search_course tool is a tiny RAG system: it splits every lesson into sections (chunks), scores them by keyword overlap with your question (retrieval), and gives the best ones to the model (generation). Upgrading it to embeddings would be a great portfolio project.
