In plain English

An AI engineer is a software engineer who builds products on top of existing AI models instead of training new ones. They take a model that's already trained (Claude, GPT, Gemini or an open model) and turn it into something useful: a support bot, a "chat with your docs" tool, a coding assistant.

Think of it like cars: one person designs engines, another builds a great car around an engine they bought. The AI engineer builds the car. You don't need a PhD. You need solid software skills plus an understanding of how models behave.

Why it matters

Adding AI used to mean collecting data, training a model and running GPUs for months. Hosted model APIs turned that into a single HTTP call. The bottleneck moved from building models to building good products with them, and that created huge demand for people who can do it reliably.

How it works

The AI engineer works in the layer between the product and the model:

Users + productthe people the app serves
AI engineering layer ← you are hereprompts, context, tools, retrieval, evals, guardrails
Model APIalready-trained models you call over HTTP
Model trainingresearch labs and ML teams

The daily work is a loop: define the task → build → evaluate → diagnose → iterate. Because model output isn't deterministic, measuring quality (evals) is as important as building.

AI engineer vs ML engineer vs data scientist

AI engineer

  • Builds on existing models
  • Prompts, RAG, tools, agents, evals
  • Cares about UX, cost, latency, safety

ML engineer

  • Trains and serves models
  • Datasets, training loops, GPUs
  • Cares about accuracy, throughput

Data scientist

  • Finds insight in data
  • Statistics, notebooks, dashboards
  • Communicates to decision-makers

The core skills

  1. Software engineering: Python or TypeScript, APIs, JSON, Git, deploying a service.
  2. Model literacy: tokens, context windows, why models hallucinate.
  3. Prompt & context engineering: clear instructions, examples, feeding the right data. Lesson 2 →
  4. RAG: searching your documents so the model answers from your data. Lesson 3 →
  5. Tools & agents: letting the model call functions and take actions in a loop. Lesson 4 →
  6. Evals & production: testing quality, controlling cost, latency and safety.

What the work looks like in code

The agent on this page is itself a small AI engineering project. Every step is one HTTP request that includes the conversation and a list of tools:

const res = await fetch(API_URL, {
  method: "POST",
  body: JSON.stringify({
    system: "You are an AI engineering tutor agent.",
    messages: history,          // the whole conversation so far
    tools: [searchCourse, webSearch, gmailSearch, draftEmail, ...]
  })
});
// If the model asks for a tool, run it, append the result
// to history, and call the API again until it answers.
Tip
That loop (the model picks a tool, code runs it, the result goes back) is all an "agent" is. Watch the 🔧 steps in the chat to see it happen.

How to get started

  1. Get comfortable building a small web app or API.
  2. Call a model API and build a simple chatbot.
  3. Add retrieval over your own documents.
  4. Give it tools to call (turning it into an agent, like this one), then write evals to measure it.
  5. Ship 2–3 small projects to GitHub as your portfolio.
